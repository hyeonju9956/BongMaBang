# 상세설계서

## 1. 저장소 파일 구성

### 프런트엔드 진입점

| 경로 | 책임 |
|---|---|
| `index.html` | 메인 페이지 구조. 인증 확인 후 메인 모듈을 시작한다. |
| `login.html` | 계정 로그인 화면 및 복귀 경로 처리 |
| `editor/index.html` | DB 에피소드 편집기와 계정 로그인 |
| `editor/admin.html` | 승인 요청 목록·비교 상세 및 사용자 계정 관리 |
| `css/tokens.css`, `layout.css`, `components.css`, `responsive.css` | 메인 사이트 디자인 토큰·레이아웃·컴포넌트·반응형 |
| `css/editor.css`, `css/login.css`, `css/admin-approval.css` | 편집기·로그인·승인 화면 스타일 |

각 프런트엔드 HTML은 `js/api-config.js`를 모듈 스크립트보다 먼저 로드한다. API origin을 변경할 때는 이 설정 파일을 수정한다.

## 2. 브라우저 데이터 처리

### 메인 화면 에피소드 로딩

1. `index.html`은 인증 대기 중 본문을 숨긴다.
2. `site-auth.js`가 `GET /api/auth/me`를 요청한다. 토큰이 없거나 유효하지 않으면 `login.html?next=...`로 이동한다.
3. 인증 성공 시 `main.js`를 동적으로 불러온다.
4. `data.js`가 `GET /api/episodes`와 `data/squad.json`을 병렬 조회한다. **에피소드 API 오류 시 정적 JSON으로 대체하지 않고 오류를 표시한다.**
5. `data.js`는 `era`, `title`, `text`, `who`, `bright` 타입을 확인하고 `index`, `number`, `searchText`를 화면용으로 구성한다.
6. `main.js`가 검색·시기 목록·별자리·본문 렌더러를 연결한다.

### 공통 API 클라이언트

- 요청 주소는 `${BONGMABANG_API_BASE}/api${path}` 형식이다. origin 끝의 `/`는 제거한다.
- JSON body가 전달되면 기본 `Content-Type: application/json`을 붙인다.
- 토큰이 있으면 `Authorization: Bearer <token>`을 붙인다.
- 비정상 HTTP 응답은 API의 `error`, `fields`, HTTP status를 담은 `ApiError`로 던진다. 네트워크 연결 실패는 status `0`으로 표시한다.
- `api()`는 성공 JSON을 반환하며 204 응답은 `null`로 반환한다. `apiRequest()`는 파일 다운로드처럼 원시 `Response`가 필요한 요청에 사용한다.
- 토큰 저장소와 key 이름은 `api-client.js`에 단일화되어 있다.

## 3. 서버 및 데이터 저장 설계

### MongoDB 컬렉션

| 컬렉션 | 주요 필드 | 용도 |
|---|---|---|
| `episodes` | `_id`, `era`, `title`, `who`, `text`, 선택 `bright`, `order`, `version` | 서비스 에피소드 원본. `order` 기준으로 표시하며 수정 시 `version`을 증가시킨다. |
| `users` | `_id`, `username`, `passwordHash`, `role`, `active`, 생성 메타데이터 | 관리자 및 일반 계정. 아이디 unique index. |
| `changeRequests` | `_id`, `action`, 변경 `payload` 또는 `ids`, 당시 `before`, `status`, 제출·결정자와 시각 | 일반 사용자 승인 요청의 원문과 제안, 처리 상태 보관 |
| `settings` | `_id: "episodes"`, `orderVersion` | 전체 에피소드 순서의 동시 변경 감지 버전 |

서버 시작 시 에피소드 순서, 사용자 고유 아이디, 요청 상태·생성 시각, 요청 사용자·생성 시각 index를 준비한다. `settings.episodes` 상태 문서는 없으면 초기화한다.

### 승인 및 동시 변경

- `update`/`delete` 요청은 에피소드 `baseVersion`을 제출한다. 요청 등록 시 현재 버전이 일치해야 하며, 승인 시에도 다시 확인한다.
- `reorder` 요청은 `orderVersion`과 모든 에피소드 ID의 새 순서를 저장한다. 제출·승인 시 전체 목록과 버전을 확인한다.
- 관리자의 에피소드 수정·삭제는 `If-Match` 버전으로 동시 수정을 검사한다. 순서 변경은 `If-Match`의 순서 버전을 사용한다.
- 충돌은 HTTP 409로 응답하며 기존 데이터에 덮어쓰지 않는다.
- 전체 순서를 변경할 때 기존 unique order 충돌을 피하도록 우선 임시 음수 순서를 기록한 후 `0..n-1`로 기록한다. 이 동작은 transaction 안에서 수행한다.
- 요청 승인 처리, 삭제 후 순서 압축, 관리자 생성·삭제·재정렬은 transaction을 사용한다. replica set이 필요하다.

## 4. 에피소드 데이터 계약

외부 JSON 배열 항목:

```json
{
  "era": "고1",
  "title": "이야기 제목",
  "who": ["인물 이름"],
  "text": "이야기 내용",
  "bright": true
}
```

| 필드 | 규칙 |
|---|---|
| `era` | 필수 문자열, trim 후 비어 있지 않음, 최대 200자 |
| `title` | 필수 문자열, trim 후 비어 있지 않음, 최대 200자. 중복 허용 |
| `text` | 필수 문자열, trim 후 비어 있지 않음, 최대 100,000자 |
| `who` | 선택 문자열 배열. 생략 시 빈 배열, 각 항목 trim 후 빈 값 제거, 항목당 최대 100자·최대 100명 |
| `bright` | 선택 boolean. 생략은 false와 같음. 내보내기에는 true만 포함 |
| `order`, `_id`, `version` | DB 내부 관리 필드이며 다운로드 JSON에는 포함하지 않음 |

API의 `GET /api/episodes`는 각 에피소드에 DB `id`, `order`, `version`을 포함한다. 다운로드 JSON은 기존 정적 사이트와 호환되는 필드만 배열로 내보낸다. 전체 검증 규칙은 [편집기 전환 사양](editor-spec.md)을 기준으로 한다.

## 5. API 목록

모든 경로는 `/api` prefix를 사용한다. “공개”는 인증 없이 호출 가능하다는 뜻이고, 프런트엔드 페이지가 로그인을 요구하는지와는 별도다.

| Method | 경로 | 접근 | 기능 |
|---|---|---|---|
| `GET` | `/health` | 공개 | API 및 MongoDB ping |
| `POST` | `/auth/login` | 공개, IP별 로그인 시도 제한 | 계정 인증 및 12시간 토큰 발급 |
| `GET` | `/auth/me` | 로그인 사용자 | 현재 사용자와 역할 반환 |
| `POST` | `/auth/logout` | 로그인 사용자 | 현재 구현은 204 응답. 토큰은 브라우저에서 지우며 서버 측 폐기는 하지 않음 |
| `GET` | `/episodes` | 공개 | 순서대로 전체 에피소드와 `orderVersion` 조회 |
| `GET` | `/export` | 공개 | 전체 JSON 다운로드 |
| `GET` | `/requests/mine` | 로그인 사용자 | 본인 요청 최근 최대 100건 |
| `POST` | `/requests` | 일반 사용자 | create/update/delete/reorder 승인 요청 제출 |
| `GET` | `/admin/requests` | 관리자 | 대기 요청 최대 500건 조회 |
| `POST` | `/admin/requests/:id/approve` | 관리자 | 요청 검증 후 transaction으로 승인·반영 |
| `POST` | `/admin/requests/:id/reject` | 관리자 | 요청 거절, 선택적 사유 최대 500자 |
| `GET` | `/admin/users` | 관리자 | 일반 사용자 계정 목록 |
| `POST` | `/admin/users` | 관리자 | 일반 계정 생성 |
| `PATCH` | `/admin/users/:id` | 관리자 | 일반 계정 활성화·비활성화 |
| `POST` | `/admin/episodes` | 관리자 | 에피소드 즉시 추가 |
| `PATCH` | `/admin/episodes/:id` | 관리자 | `If-Match` 버전 확인 후 수정 |
| `DELETE` | `/admin/episodes/:id` | 관리자 | `If-Match` 버전 확인 후 삭제 및 순서 압축 |
| `POST` | `/admin/episodes/reorder` | 관리자 | `If-Match` 순서 버전 확인 후 순서 변경 |

유효성 오류는 422, 로그인·세션 오류는 401, 권한 오류는 403, 버전·요청 충돌은 409, 필요한 `If-Match` 누락은 428을 사용한다. 잘못된 JSON은 400이다.

## 6. 인증·보안 처리

- 로그인 아이디는 영문·숫자 및 `_ . -` 조합 3~32자, 비밀번호는 12~256자다.
- 비밀번호 원문은 저장하지 않고 scrypt 해시로 저장한다.
- 세션은 payload와 HMAC-SHA256 서명을 결합한 토큰이며 수명은 12시간이다. 보호 API마다 서명·만료·사용자 활성 상태를 검사한다.
- 로그인은 IP별 15분 구간 최대 10회로 제한한다.
- 보호 API에서 `requireAuth`가 사용자를 확인한 뒤 `requireRole`이 관리자/일반 사용자 권한을 적용한다.
- Helmet을 사용하고, 브라우저 CORS 요청은 same-origin 또는 `FRONTEND_ORIGINS`에 정확히 등록된 origin만 허용한다.
- 프런트엔드 토큰은 `sessionStorage`에 저장된다. 페이지 종료 시 정리되며 서버 측 토큰 폐기는 구현되어 있지 않다.
- `.env` 및 운영 비밀값은 저장소에 올리지 않는다. `.gitignore`에서 `backend/.env`를 제외한다.

## 7. 설정·초기화·검증

### 주요 환경 변수

| 변수 | 설명 |
|---|---|
| `MONGODB_URI` | MongoDB 연결 URI. replica set 필요 |
| `MONGODB_DB` | DB 이름, 기본 `bongmabang` |
| `SESSION_SECRET` | 32자 이상의 임의 HMAC 비밀값 |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | 최초 관리자 생성 정보. 비밀번호 12자 이상 |
| `PORT` | API 포트, 기본 3000 |
| `FRONTEND_ORIGINS` | 쉼표로 구분한 허용 프런트엔드 origin 목록 |
| `BONGMABANG_API_BASE` | 브라우저 전역 설정명. 실제 값은 `js/api-config.js`에서 지정 |

### 명령

```powershell
npm --prefix backend install
npm run import:episodes
npm start
npm test
```

`npm run import:episodes`는 `data/episodes.json`을 검증하고 `episodes` 컬렉션이 비어 있을 때만 적재한다. 데이터가 있으면 덮어쓰지 않고 종료한다. 테스트는 인증·검증·기존 JSON 호환성과 DB API 응답을 모의한 메인 화면 데이터 로딩을 확인한다. 실제 운영 MongoDB 연결이나 브라우저 end-to-end 검증을 대신하지 않는다.
