# 에피소드 편집기 전환 사양

## 목표와 범위

- 기존 브라우저 로컬 편집·파일 직접 저장 방식은 폐기하고, 백엔드 API를 통해 에피소드 데이터를 읽고 수정한다.
- 백엔드 데이터베이스를 원본으로 삼는다. 브라우저는 원본 JSON 파일과 일치하는지 비교하거나 로컬 파일에 저장하지 않는다.
- 전체 에피소드 JSON 내보내기는 유지한다. 내보내기는 백엔드의 한 시점 스냅샷을 `episodes.json`으로 다운로드한다.
- 관리자는 에피소드 변경을 즉시 저장한다. 일반 사용자는 변경 요청만 제출할 수 있고, 승인 전에는 실제 에피소드 데이터에 반영하지 않는다.

## 데이터 저장소 권고

JSON 다운로드가 필요하다는 이유만으로 MongoDB를 선택할 필요는 없다. JSON은 API와 파일의 교환 형식이고, 저장소 선택은 데이터 구조와 운영 방식에 맞춰야 한다.

현재 에피소드 구조는 JSON 문서로 다루기 쉽고, DB에 `order` 숫자 필드를 두면 표시 순서도 명시적으로 관리할 수 있다. 따라서 **MongoDB를 사용해도 문제없다**. 조회와 내보내기 때 `order` 오름차순으로 정렬하고, 기존 JSON 호환성을 위해 내보내기 결과에서는 `order` 필드를 제외한다.

관계형 제약 조건과 트랜잭션을 우선하거나 팀의 기존 운영 환경이 PostgreSQL이라면 PostgreSQL도 좋은 선택이다. 어느 DB를 쓰더라도 내보내기 JSON의 형식과 배열 순서는 DB 내부 형식과 분리해 보장한다.

## 데이터 계약

에피소드 JSON은 기존 사이트 호환성을 위해 배열을 유지한다. 배열 순서가 사이트의 표시 순서이며, 내보내기에서도 그대로 보존한다.

```json
{
  "era": "고1",
  "title": "이야기 제목",
  "who": ["인물 이름"],
  "text": "이야기 내용",
  "bright": true
}
```

- `era`, `title`, `text`: 문자열이며 공백 제거 후 빈 값은 허용하지 않는다.
- `era`와 `title`은 최대 200자, `text`는 최대 100,000자다.
- `who`: 문자열 배열. 입력은 선택이며 생략 시 빈 배열로 저장한다. 각 항목의 앞뒤 공백을 제거하고 빈 항목을 제외한다.
- `who`의 인물 이름은 최대 100자이며, 한 에피소드에서 최대 100명까지 허용한다.
- `bright`: 선택 boolean. 생략은 `false`와 같은 의미로 처리하고, 내보낼 때는 기존 데이터 호환성을 위해 `true`인 경우에만 포함한다.
- `era`는 `squad.json`의 시기 목록에 반드시 존재할 필요가 없다. 새 시기 입력을 허용한다.
- 제목 중복은 허용한다. 제목은 식별자가 아니며 에피소드 순서와 별개로 취급한다.
- 편집·삭제·순서 변경은 서버가 관리하는 에피소드 식별자를 사용한다. `order`는 0부터 시작하는 정수로 저장하고, 순서 변경 때 서버가 전체 순서를 갱신한다. 식별자와 `order`는 사이트 내보내기 데이터에 노출하지 않는다.
- 수정·삭제 요청에는 읽어 온 `version`을 `If-Match`로 보내며, 다른 편집이 먼저 반영된 경우 `409 Conflict`를 돌려 데이터 덮어쓰기를 막는다.

## Validation 설계

Validation은 **요청 데이터의 형식과 업무 규칙, 저장 데이터의 무결성**을 확인한다. 로컬 파일 선택, 파일명, 로컬 파일과 서버 데이터의 일치 여부, 파일 해시 비교는 검증 대상이 아니다.

1. **클라이언트 입력 검사**: 필수값 누락과 잘못된 입력을 저장 전에 표시한다. 이는 사용성 검사일 뿐이며 서버 검증을 대체하지 않는다.
2. **서버 요청 검사**: 모든 생성·수정 요청에서 필드 타입과 위 데이터 계약을 검증한다. 문자열은 서버에서도 공백 제거 후 필수값 여부를 검사하고, `who`의 항목 타입과 `bright`의 boolean 타입을 확인한다. 잘못된 요청은 저장하지 않고 필드별 오류와 함께 명시적인 4xx 응답을 반환한다.
3. **저장 무결성 검사**: 저장 시 서버 검증을 다시 적용한다. `order`는 음수가 아닌 정수여야 하며, 순서 변경은 전체 에피소드 식별자가 빠짐이나 중복 없이 한 번씩 포함되는지 검사한 뒤 `order`를 0부터 다시 부여한다. 동시 수정 충돌은 덮어쓰지 말고 충돌 응답으로 알린다.
4. **전체 JSON 내보내기 검사**: 서버에서 전체 에피소드 스냅샷을 `order` 오름차순으로 만든 뒤 내부 식별자와 `order`를 제외하고 JSON 직렬화한다. 모든 레코드가 데이터 계약을 만족하는지 확인하고 성공 시 `application/json` 다운로드로 응답한다. 실패 시 부분 파일이나 성공 응답 대신 명시적인 오류를 반환한다.

## 기능 요구사항

- 서버에서 목록을 읽고 검색·시기 필터링을 제공한다.
- 에피소드 추가, 수정, 삭제 및 순서 변경을 서버 API로 수행한다.
- 성공·실패 상태를 사용자에게 표시하고, 저장되지 않은 편집 내용이 사라지지 않도록 한다.
- 전체 내보내기는 일부 검색 결과나 현재 선택 항목이 아니라 서버의 모든 에피소드를 포함한다. 다운로드는 읽기 전용이며 서버 데이터를 변경하지 않는다.
- 동시 편집으로 최신 데이터가 달라진 경우 사용자가 변경사항을 확인할 수 있도록 충돌을 알린다.
- 목록 읽기와 전체 내보내기는 공개한다. 관리자와 일반 사용자는 로그인 계정을 사용한다. 일반 사용자의 변경 요청은 관리자 전용 `/editor/admin.html` 화면에서 승인·거절하며, 화면은 15초마다 대기 요청을 갱신한다. 계정 생성과 비활성화도 관리자 화면에서만 수행한다.

## 구현 API

| Method | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/health` | API와 MongoDB 연결 상태 |
| `GET` | `/api/episodes` | `order` 순서의 전체 에피소드 및 순서 버전 |
| `GET` | `/api/export` | 전체 에피소드를 기존 JSON 배열로 다운로드 |
| `POST` | `/api/auth/login` | 계정 로그인 및 12시간 세션 발급 |
| `GET` | `/api/auth/me` | 현재 세션 계정·역할 확인 |
| `POST` | `/api/requests` | 일반 사용자의 추가·수정·삭제·순서 변경 요청 등록 |
| `GET` | `/api/requests/mine` | 로그인한 사용자의 최근 요청 |
| `GET` | `/api/admin/requests` | 관리자의 승인 대기 요청 목록 |
| `POST` | `/api/admin/requests/:id/approve` | 대기 요청 승인 및 데이터 반영 |
| `POST` | `/api/admin/requests/:id/reject` | 대기 요청 거절 |
| `POST` | `/api/admin/users` | 일반 사용자 계정 발급 |
| `GET` | `/api/admin/users` | 계정 목록 |
| `PATCH` | `/api/admin/users/:id` | 일반 사용자 계정 활성화·비활성화 |
| `POST` | `/api/admin/episodes` | 관리자 에피소드 1건 즉시 추가 |
| `PATCH` | `/api/admin/episodes/:id` | `If-Match` 버전 확인 후 즉시 수정 |
| `DELETE` | `/api/admin/episodes/:id` | `If-Match` 버전 확인 후 즉시 삭제 |
| `POST` | `/api/admin/episodes/reorder` | `If-Match` 순서 버전 확인 후 즉시 순서 변경 |

승인 적용, 에피소드 추가·삭제와 전체 순서 변경은 MongoDB transaction을 사용하므로 replica set 구성이 필요하다. 최초 적재는 기존 `data/episodes.json`을 DB가 비어 있을 때만 추가하는 `backend/scripts/import-episodes.js`로 수행한다.

최초 관리자 계정은 `ADMIN_USERNAME`과 `ADMIN_PASSWORD` 환경 변수로 DB에 한 번만 생성한다. 일반 계정은 관리자 화면에서 발급한다. 비밀번호는 scrypt 해시로 저장하며, 세션은 12시간 후 만료된다. 로그인은 IP별 15분 동안 최대 10회로 제한한다. 변경 요청 알림은 별도 관리자 화면의 15초 주기 새로고침으로 제공하며 이메일 발송은 포함하지 않는다.

## 완료 조건

- DB에 저장된 전체 에피소드를 기존 사이트가 읽을 수 있는 JSON 배열로 다운로드할 수 있다.
- 내보낸 배열의 개수와 순서가 내보내기 시점의 서버 데이터와 일치한다.
- 잘못된 입력은 클라이언트 검사와 무관하게 서버에서 거부되며, 로컬 파일 비교 없이 내보내기가 동작한다.
- 권한 없는 사용자는 서버에서 생성·수정·삭제·순서 변경을 수행할 수 없다.
